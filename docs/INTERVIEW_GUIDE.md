## 第一部分：项目全貌

### 1.1 四档口述稿

**10 秒版**：我做的是一个 agent 测试时强化学习框架：让会调用工具的 LLM 在部署期
边工作边自学，配两道安全闸门防学歪；在三个模型上验证后得出一个机制级结论——
这个能力级别的模型不产生可学习的正样本，问题在"探索缺口"而不是算法。

**1 分钟版**：电商客服 agent 场景：用户要退换货，agent 要调用一串工具、真的改
数据库才算成功。传统微调是"上岗前培训"，测试时 RL 是"上班中学习"——每个工单
结束后用结果做奖励信号在线更新。风险是会学歪，所以做两层门控：局部门检查工具
回执中的证据冲突（重复犯同样错、没验身份就动手），冲突清零学习信号；全局门用
经验-伯恩斯坦检验决定新版本能否上线，无统计证据就回滚。结果：门控全程有效
（投毒适配器被拦截），主实验是空结果——6 种配置、采样和提示基线全卡在 0.109。
深挖原因：Qwen 模型 400+ 工单里从未执行状态变更操作，正样本结构性不存在。

**3 分钟版**：
1. 定位（10s）：agent 测试时 RL + 双尺度安全门控，已开源 v0.1。
2. 问题（30s）：退换货例子；大模型 agent 上岗后不会进步；无门控更新会学歪
   （信用分配错、证据污染、在错误行为上强化）。
3. 方法（60s）：更新层（结构化动作组信用 + 优势加权策略梯度 + LoRA 0.5%）；
   局部门（E_hard 三类冲突 → 清零，fail-closed）；全局门（配对影子评估 +
   经验-伯恩斯坦 e-process，α=0.05，参数经 162 组覆盖模拟器冻结）。
4. 结果（40s）：正结果——门控有效（投毒被 ROLLBACK、Llama 无效操作被清零）；
   空结果——密封 46 题全部 0.109 零翻转；机制证据——漂移 0.08→4.0、25/46 行为改变；
   机制解释——Qwen 从不执行状态变更，正样本结构性缺失。
5. 结论（20s）：交付可复现框架 + 机制级结论 + 门控验证；配方：先换会"动手"的基座。

**8 分钟深度版**：3 分钟版 + 按顺序展开：环境与协议（2min）→ 训练机制（2min）→
门控机制（2min）→ 实验全景（1.5min）→ 工程故事（0.5min）。

### 1.2 一道题的完整走查

任务 0：用户 Yusuf Rossi（邮编 19122）收到订单 #W2378156，想把机械键盘换成青轴
版本、智能温控器换成支持 Google Home 的；若无"青轴+RGB+全尺寸"键盘则换无背光。

- 标准答案（隐藏参考轨迹）5 步：查用户 ID → 查订单 → 查两个商品 → **执行换货**。
- 实际模型行为：查用户、查订单，然后回复"已为您处理"——**没有执行换货**，
  数据库状态未变 → 判 0 分。这是 50% 失败模式（早停）的典型样本。
- Llama 对照：它会尝试换货，但订单号是编造的 #W0000000、用户 ID 是编造的
  yusuf_hernandez_123 → 系统"查无此单" → 局部门识别"重复错误重试 + 操作对象
  非真实实体"，逐条清零信用。

### 1.3 一轮训练的完整走查（一个工单内部，约 30-90 秒）

① Agent 作答（政策+工具清单 → 生成工具调用）
② 环境执行 → 拿到回执（E_hard 证据）
③ 循环 ①-② 直到停止或 20 轮上限
④ 判分：比对数据库最终状态（隐藏评估器）
⑤ 局部门：三类冲突检测
⑥ 信用分配：成功回合全动作 +0.5；失败回合识别/查询 0、修改 −0.3、首停 −0.3；
   冲突组直接 0（abstain）
⑦ 梯度更新：动作 token 片段的加权对数概率 → 4 步 AdamW 更新 LoRA
⑧ 漂移护栏：与基座行为差异 >2.0 → 学习率减半（1e-6 兜底）
⑨ 每 5 个工单：全局门影子评估（候选 vs 父版本考同样新题）
68 个工单后，用密封 46 题判最终分。

## 第三部分：30 个必答题（含追问防线）

### A 类：价值与动机

**A1. 空结果的意义？** 三层：机制级结论排除无效方向 / 门控被真实验证 /
框架可复现。
> L2 追问"凭什么信机制结论"：三组独立证据指向同一结论（同族 4B→9B 一致、
> 成功轨迹审计无合法状态变更、提示/采样/回放三路径全无效）。

**A2. 为什么不换更大模型验证？** 已试 3 模型；4B/9B 一致、Llama 行为不同 →
指向能力边界。边界写进报告，给出可执行判断标准。
> L2"结论只对 ≤9B 成立？"：对，这就是"确定适用范围"，并且配方可直接指导下一步。

**A3. 最大技术贡献？** 双尺度门控的第一个完整开源实现，两层都在真实模型上
端到端验证（不是论文公式）。

**A4. 重做会改变什么？** (1) 第一天做能力探测（10 分钟避免数天无效训练）；
(2) 直接用 transformers 原生 rollout，省掉 vLLM LoRA 静默失效的排查。

**A5. 体现你哪些能力？** 算法（GRPO 变体/信用/KL/护栏）、工程（双卡/显存/静默
bug 排查）、研究（机制分析/诚实测量/统计设计）。

### B 类：算法深层

**B6. 优势怎么归一化？** 不用全局归一化（二值稀疏奖励下方差失真）；用分组基线 +
固定系数（成功 +0.5；失败按组区分）。极端稀疏下信号可预期。

**B7. token 级梯度怎么定位？** 渲染完整对话 → 字符偏移定位最后一段
`<tool_call>...</tool_call>` → tokenizer offset mapping 映射 token 区间 →
只在该区间算对数概率和梯度。

**B8. 为什么贪心 rollout？** 采样（temp0.7）会让模型飘出工具模式、给错误行为
分配信用；贪心保证 rollout 与评估一致且可复现。

**B9. 影子评估为什么 20 个样本？** 数据预算（干净池有限）+ 成本（每样本两次
轨迹）。不足 n=512 提交门槛 → 必然 INCONCLUSIVE → fail-closed（设计上的诚实）；
门控有效性由覆盖模拟器在 n=512 规模验证。
> L2"那门控岂不是永远不开门"：覆盖模拟器证明真有改进时有 64.6% 提交概率——
> 是"小样本保守"不是"永远不开"。

**B10. 怎么区分保护与僵化？** 保护性：投毒实验正确拦截（增益下界 −0.40）、
Llama 无效操作被清零；非僵化性：模拟器证明真改进时可提交。

**B11. e-process vs SPRT/固定样本？** SPRT 需似然比结构假设；固定样本不允许
中途看结果。e-process 的 anytime-valid 正适合"随时可停"，经验-伯恩斯坦变体
用实测方差收紧界。

**B12. KL 具体形式？** 逐 token"参考对数概率 − 当前对数概率"取正值，β=0.1；
参考是冻结基座（统一锚点）。

**B13. LoRA r=16 够吗？** 有实测漂移和行为改变 → 瓶颈在信号不在容量（先排除
容量假说的设计）。

**B14. 损失曲线？** 加权对数概率本身无绝对意义；**用行为指标和结果指标讲 RL，
不用损失曲线**。

**B15. GRPO vs PPO？** 选 GRPO（省价值网络）。回合级二值奖励下进一步简化为
组基线+固定系数——由数据反推的设计。

### C 类：实验设计与统计

**C16. 怎么证明不是代码 bug？** 四层：机制生效证据（漂移/行为改变）、负向对照
（发生过坍缩）、跨模型可解释差异、复现工程（种子/校验/测试）。
> L2"漂移会不会本身就是 bug"：两个独立框架交叉验证；且有方向语义（信用写错时
> 漂移暴涨+工具调用消失）。

**C17. 1-2 个种子够吗？** 对效应量不够（不声明效应量）；对机制验证够（全称命题
的反例搜索）。另做匹配算力与负向对照。

**C18. 为什么是 0.109？** 46 题对 5 题；5 次成功全部是查询类任务，没有一次
需要真改数据库——这个分解本身就是发现。

**C19. 怎么排除"环境太难"？** 环境准入验证过 0.167 在可提升区间；Llama 在
同环境行为完全不同 → 环境允许这类行为，Qwen 不作为是模型问题。

**C20. 为什么不用部分信用？** 精确匹配不可作弊（部分分有被钻空子风险）；代价
是部分进步不可见——已写进 forward-looking 作为改进方向。

**C21. 有预注册吗？** 轻量版：决策日志 12 条，每条含"决策/证据/替代方案/
拒绝原因/可证伪条件"，先记录假设和判据再跑实验。

### D 类：工程与调试

**D22. 最难的工程问题（vLLM 静默失效）？** 现象（加载成功但生成一致）→ 定位
（transformers 交叉验证漂移 10.6 → vLLM 混合架构 LoRA 缺陷）→ 解法（rollout
移入训练进程）→ 原则（加载成功必须有行为级验证）。

**D23. 还遇到什么？** 训练态 dropout 污染生成（从"训练行只有 2 个 token"抓出）；
混合线性注意力反向传播 in-place 崩溃（装 fla 解决）；统一负向信用导致工具调用
坍缩（催生失败感知信用）。

**D24. 显存怎么管？** 双卡（服务/训练各一）；分块 logsumexp、梯度检查点、工具
返回截断；峰值 20.5GB/32GB。

**D25. 测试与 CI？** 17 单元测试（门控 5/解析器 6/信用 6）；CPU 可跑（核心
证据类型已从环境依赖解耦）。

**D26. 复现性？** 固定种子、贪心评估、SHA256 校验、一键复现、数据源固定
commit、兼容性档案（版本+服务器 flag 全锁定）。

### E 类：开放与反思

**E27. 给一个会做状态变更的模型怎么验证框架？** 三步：能力探测（合法轨迹出现
率 >10%）→ 正样本密度（成功回合 ≥25%）→ 部分信用评估；然后跑同模型冻结 vs
TTRL vs BoN 对比。

**E28. 测试时 RL 最大开放问题？** 探索缺口——方法层工作都假设"模型会做出值得
学习的动作"，当目标行为在输出分布外时框架无事可做；如何注入结构化探索是下一步。

**E29. 最大成长？** 从结果导向转向机制导向：效果不好先问为什么，把假设变成
10 分钟的探测实验。

**E30. 你会怎么批评这个项目？** 三条：单环境（泛化性有限）、精确评估（部分
进步不可见）、单种子（无效应量置信区间）——都写进 limitations，给接手者准确起点。

## 第四部分：压力面试应对

- **"这不就是失败的项目？"**：不辩解，接住（"结果确实没有提升，我放在第一句；
  但它把失败追到了机制层面——两分钟讲一下怎么定位到根因的"）。
- **被问到不会的**：给相邻知识 + 给行动路径，不硬编。
- **被打断要求一句话**：切 10 秒版定位句，反问"想展开算法还是工程？"
- **"都是模型能力问题，跟你无关"**：承认对的部分 + 补上没看到的层次（结论本身
  是方法论胜利 / 门控可迁移 / 配方可执行）。
