# 面试手册 · agent-ttrl2（测试时强化学习 + 双尺度安全门控）

> 用途：秋招面试准备。第一部分是 3 分钟口述稿；第二部分是数字速查；
> 第三部分是 20 个必答题的标准答案；第四部分反问建议；第五部分诚信说明。

## 第一部分：项目介绍（3 分钟口述版）

### 1. 一句话定位（10 秒）

我做的是一个 **agent 测试时强化学习框架**：让会调用工具的 LLM 智能体在部署期
"边工作边自学"，并给它设计了两道安全闸门防止学歪；在三个模型上做了彻底验证后，
得出一个机制层面的诚实结论——**这个能力级别的模型不产生可学习的正样本，是
"探索缺口"而不是算法问题**。

### 2. 问题背景（30 秒，带例子）

场景是电商客服 agent：用户说要退换货，agent 需要调用一串工具（查用户、查订单、
查商品、**真正执行退换货改数据库**），最后系统检查数据库改对没有。
现在的大模型 agent 通病是：**上岗后不会进步**。测试时 RL 的思路是让它边做边学。
但无门控的更新有三个风险：信用分配错误、被污染的证据带偏、以及在错误行为上强化。

### 3. 方法（60 秒，三层）

- **更新层**：每处理完一个工单，把轨迹按结构化动作组（识别/查询/修改）分配信用，
  做优势加权的策略梯度更新，只训练挂在冻结基座上的 LoRA 适配器（0.5% 参数量）。
- **局部门（动作级）**：基于工具回执（E_hard 证据）做冲突检测——重复用同一错误
  参数重试、未验证身份就修改、修改的不是当前用户的订单——冲突则整组信用清零，
  fail-closed。
- **全局门（部署级）**：每次更新产出的候选版本，要和父版本做配对影子评估，用
  **经验-伯恩斯坦 e-process**（α=0.05）判定"增益下界≥1% 且危害上界≤10%"才允许
  提交，否则回滚。门控参数由 162 组配置的覆盖模拟器事先冻结。

### 4. 结果（40 秒，按重要性排序）

- **先说正结果**：双门控机制全程有效——故意投毒的适配器被全局门 ROLLBACK 拦截；
  Llama 模型的无效操作尝试被局部门逐条清零信用。安全机制在真实数据上验证。
- **主实验是诚实的空结果**：密封 46 题上，冻结基线 0.109；6 种更新配置 × 2 种子、
  Best-of-4（两种温度）、完美提示词——**全部 0.109，零翻转**。但机制验证生效：
  行为漂移 0.08→4.0，25/46 题行为改变——更新真生效了，只是没改成正确结果。
- **机制解释**：Qwen 系列在 400+ 工单里**从未执行过一次状态变更操作**——强化学习
  需要的正样本结构性不存在（探索缺口）。

### 5. 结论（20 秒）

交付物：完整可复现的双门控框架 + 排除大量无效方向的机制级结论 + 安全机制在两种
真实失败模式上的验证。对后续研究者的指引：**想做出正结果，先换一个真正会执行
多步状态变更的基座模型。**

## 第三部分：20 个必答题

### A 类：项目价值

**Q1：空结果的项目意义是什么？**
三层意义：(1) 把"为什么不行"查到机制层面——≤9B 模型不产生策略合法的状态变更
轨迹，正样本结构性不存在，排除了整个方向上一大类无效尝试；(2) 安全机制在两种
真实失败模式上被完整验证（投毒拦截 + 无效操作清零）；(3) 框架和评测协议完全
可复现，后续研究者可直接换模型重跑。

**Q2：为什么不直接换更大模型验证结论？**
已试三个模型：Qwen3.5-4B/9B 行为完全一致（都不执行状态变更），Llama-3.1-8B
会尝试但操作无效——三组证据指向"能力边界"而非算法缺陷。更大模型的完整验证
超出单人算力预算，但我把边界条件和四步配方写进了报告的 forward-looking 部分。

**Q3：测试时 RL 方向的现状？你的位置？**
两类工作：一类做"能学多少"（如 TTRL 类方法直接对测试流做 RL），一类做"怎么不
学坏"（验证器、门控、回滚）。我的工作属于第二类，是第一个把"动作级证据门控 +
部署级统计门控"两层机制完整实现并端到端验证的系统。贡献是工程+测量完整性，
不是新优化器。

### B 类：方法与算法

**Q4：什么是测试时强化学习？和传统微调的区别？**
传统微调 = 上岗前培训（离线、周期以天计）；测试时 RL = 上班中学习（在线、
奖励来自部署环境反馈、更新频率高）。代价是必须处理"边学边错"的安全问题，
这也是项目立项的核心动机。

**Q5：更新算法是什么？GRPO 原理？**
GRPO 用"同题组内奖励均值"替代 PPO 的价值网络做基线（优势=个体奖励−组基线），
省掉 critic。我的实现是针对 agent 轨迹的变体：优势按结构化动作组
（识别/查询/修改/终止）而非整条回答计算；损失是优势加权对数概率，只对工具
调用 token 片段求梯度；外加对冻结基座的 KL 惩罚。

**Q6：信用分配怎么做的？**
"分组 + 失败感知"。(1) 第一版直觉方案（失败则全轨迹扣分）导致模型干脆不调用
工具（漂移 13 坍缩）——因为查询动作本身没错，扣它们是错误归因；(2) 改为：
成功回合所有动作 +0.5；失败回合识别/查询中性、修改 −0.3、过早终止 −0.5。
对照实验：行为损伤从 25/46 降到 9/46。(3) 局部门做最后保险：证据冲突整组清零。

**Q7：为什么要 KL 惩罚？**
约束新策略不离参考策略太远，防止坍缩、保持语言能力。β=0.1 经验值。实验发现
KL 单独不足以防坍缩，所以加漂移护栏（漂移>2.0 学习率减半，1e-6 兜底）。

**Q8：为什么用 LoRA？秩怎么定？**
(1) 资源：0.5% 参数量，单卡双进程可行；(2) 测试时 RL 更新频率高，小参数量
更稳定；(3) 适配器是天然的版本管理单元——回滚贴片比回滚全量权重便宜。
r=16 覆盖注意力 q/k/v/o + MLP gate/up/down；实测足以产生可测漂移，容量非瓶颈。

**Q9：双尺度门控为什么是两个尺度？**
两个尺度对应两个失败时机：局部门在更新前决定"这条经验该不该学"（防坏数据入
训练）；全局门在部署前决定"学完的这套该不该上线"（防累积退化）。缺一不可。

**Q10：e-process 是什么？为什么不用 t 检验？**
t 检验需事先固定样本量且假设近似正态（二值小样本不可靠）。e-process 是
anytime-valid（任意时刻查看/停止，误报率都≤α），我的经验-伯恩斯坦变体用样本
方差而非最坏界，小噪声下界更紧。判定：增益下界≥1% 且危害上界≤10% 才提交。

### C 类：实验设计与统计

**Q11：怎么证明不是代码 bug？**（最危险问题）
四层证据：(1) 机制生效的正面证据：漂移可测、25/46 行为改变——管线坏了应该没有
漂移；(2) 负向对照：出现过"更新过强导致坍缩（漂移 13）"——证明测量对变化灵敏；
(3) 跨模型可解释差异：Qwen 4B/9B 一致、Llama 完全不同——bug 不会产生模型相关
模式；(4) 复现工程：固定种子、贪心评估、SHA256 校验、17 单元测试、一键复现。

**Q12：只有 1-2 个种子，统计显著性怎么办？**
明确标注 exploratory，不宣称显著性。第一优先级是机制验证：6 种配置全部精确
等于基线、零翻转——若效应存在，至少应有方向性变化；一个都没有，这本身就是
结论。另做了匹配算力控制排除"算力不足"解释。

**Q13：匹配算力指什么？**
让被比较方案消耗相近推理预算：BoN-4 = 184 次 rollout；TTRL ≈ 200 次
（68 更新 + 92 评估 + 40 影子）。两者都 0.109——空结果不是预算问题。

**Q14：怎么保证数据无污染？**
(1) 46 道评估题从未出现在训练/信用/门控决策中（前 68 更新、后 46 密封）；
(2) 判分标准（目标数据库状态）从不进入提示词或训练信号；
(3) few-shot 实验的示例来自另一道题（任务 0），不泄漏任何评估题目标。

### D 类：工程与难题

**Q15：最难的工程问题？**（推荐 vLLM LoRA 故事）
vLLM 的 LoRA 动态加载**静默失效**：接口返回成功、模型列表可见，但生成与基座
一字不差。定位：同适配器在 transformers 加载漂移 10.6（适配器没问题）→ 确认
是 vLLM 0.26 对 Qwen3.5 混合注意力架构的 LoRA 应用缺陷。解法：改架构——训练
进程自己生成（rollout 在 transformers 里跑），适配器天然是当前版本。原则：
**serving 层的"成功"不等于"生效"，加载必须有行为级验证**。
备选：混合线性注意力反向传播 in-place 崩溃（装 flash-linear-attention）；
训练后忘切 eval 模式 dropout 污染生成（一轮实验白跑）；统一负向信用导致
工具调用坍缩（设计错误，有对照）。

**Q16：训练怎么做？显存怎么管？**
双卡：GPU1 vLLM 推理、GPU0 训练。训练需同时加载当前+参考两份模型
（8.6GB×2），峰值 20.5GB/32GB。三个优化：分块 logsumexp（不物化全词表×
序列的浮点矩阵）、梯度检查点（时间换显存）、工具返回截断到 400 字符。

**Q17：为什么测评只看数据库状态？**
划清"行为改变"与"任务完成"的界限：看模型说什么，学会说漂亮话就能得分；数据库
状态客观可重放。该设计直接支撑核心发现——"只查不改"能蒙对查询题，退换货题
必须真改数据库，而 Qwen 从不改。

### E 类：反思与开放

**Q18：给更多资源怎么做正结果？**
四步配方（均有实验依据）：(1) 换基座——先用小规模探测验证"会动手"再投入；
(2) 提高基础成功率——在 ≥0.25 的任务子集上跑，保证密集正样本；
(3) 换部分信用评估——精确状态匹配会把"部分完成"记零；
(4) 调更新强度——安全窗口已测出：漂移 0.1-2.0 健康、>5 坍缩。

**Q19：项目教给你的方法论？**
(1) 先验证"信号存在"再投入方法建设（10 分钟探测避免几天无效训练）；
(2) 空结果要追到机制层面才有价值（"效果不好"无信息量，"从不执行动作所以
无正样本"可行动）；(3) 每个数字都要有血的教训（"漂移>5 坍缩"是真坍缩过）。

**Q20：回应"就是模型太差，换 70B"？**
"我的结论和您一致——所以我把它当边界条件发现而不是算法失败。而且不是猜的：
同族 4B→9B 行为一致、另一家族会尝试但操作无效，三组证据指向能力边界。我还
给出了可执行判断标准：探测实验里出现合法状态变更轨迹，框架已就绪可直接重跑。"
